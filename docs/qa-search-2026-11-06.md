# Search and usability audit — 2026-11-06

## Fixed

- Plain resource YAML lacked a Find control. Added local Find floating inside the editor at its top right, without adding a row or resizing the text area, with match counts, case sensitivity, wraparound, next/previous and keyboard access.
- The native Edit menu lacked Find. Added it while retaining the standard macOS editing items.
- Helm values, kubeconfig settings, data editors and other dynamically created plain textareas now receive the same Find control. Read-only editors remain read-only. Monaco and terminal helper textareas are excluded from automatic attachment.
- Rich YAML and comparison editors use native Monaco Find through the visible control or shortcut.
- Find searches visible rendered page text when no text editor or log viewer owns focus. Existing table filters still search all loaded pages.
- Pod and general cluster terminal scrollback use the official xterm search add-on, including match highlighting/navigation and resize recovery. Search typing is not sent to the shell.
- Log search now receives the Find shortcut. Escape clears a nonempty log query before closing resource details.
- Find state closes when changing views or editor resource ownership; closing a resource clears the search UI.
- The terminal session acceptance test waits for renderer cleanup as well as process shutdown, addressing the asynchronous count assertion observed during the previous release build.

## Validation

The search-specific desktop suite uses an isolated demo profile. It checks deployment YAML, overlay bounds and unchanged editor height, match counts, next/previous, wraparound, match case, no matches, Escape, native Edit menu, rich editor/comparison search, logs, dynamically generated Helm values, settings, rendered page text and read-only content preservation. It issues no live cluster mutations.

The full backend and packaged desktop suites cover navigation, multi-cluster workspaces, namespace filters, Events, logs/terminals, scaling, map/display settings, palette, column controls, metrics/history, troubleshooting/saved views, forms, catalog/GitOps/extensions, connection setup, Secret controls, resource painting and persistent Kubernetes API transport.

These are fixture/demo checks, not proof of every live cluster or company proxy environment. Page Find covers rendered text; full-list filtering remains a separate table control. Terminal scrollback uses the official xterm search add-on through its own Find control; page Find does not inspect terminal rendering.
