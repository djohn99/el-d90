# el-d90 review — 2026-11-09

Scope: released 0.5.9 plus the current local, unpublished changes. Source review, full backend checks, isolated packaged Electron workflows, syntax checks, packaging and npm dependency advisories. No production resource mutations, IAM/RBAC edits, live node-debug Pods or Helm mutations were performed. This is not an exhaustive security audit or a proof of Lens feature equivalence.

## Confirmed issues fixed

| Issue | Change | Verification |
| --- | --- | --- |
| Previous AWS role's namespaces could reappear while typing after changing profiles | Clear both rendered choices and the underlying namespace search inventory on profile/region/list invalidation | AWS fixture switches profiles while requests are pending and checks that the old namespace is absent |
| Unsaved ConfigMap data edits disappeared when dismissing details | Retain drafts in bounded memory by context, namespace, name and immutable UID; restore on reopening. Explicit Cancel and successful Save clear the retained draft | Resource-data fixture dismisses/reopens multiline and added-key edits before YAML review; existing direct-save, validation-failure, cancellation and Save & Close checks remain |
| Setup guidance referred to a removed form | Direct first-run users to the visible SSO account/role discovery workflow | Source review and connection acceptance |
| Feature matrix described 0.5.0 and called delivered features absent | Replace with a current evidence-qualified matrix; archive the original comparison | [Current matrix](coverage-matrix.md); historical evidence remains in the excluded local research archive |

Draft values are never written to disk by the new retention logic. The in-memory limit is 20 ConfigMap drafts; app quit loses them. Existing backend identity/size/immutability validation and native apply confirmation remain. Successful saves that complete after dismissal clear the matching submitted retained draft; newer edits are not removed.

## Additional user-requested interaction changes

- Resource Terminal tabs connect immediately. Reopening an active terminal reuses its session; selecting a different Pod container/shell reconnects. Pending connections are guarded and stale results are stopped. Node-debug still requires the native privileged-Pod confirmation; cancelling it creates no session.
- Resource deletion, including Deployments, namespaces, volumes, Secrets and CRDs, no longer requires typed names. The native exact-target confirmation remains. Node drain retains typed-name confirmation and eviction safeguards.

The following is the historical finding inventory. Version 0.5.10 resolves these package entries with pinned overrides and rebuilds the shipped Monaco runtime from ESM with DOMPurify 3.4.17. Old generated assets are removed before building; metadata and regression tests enforce the patched sanitizer and editor contributions. A fresh npm audit returns zero advisories. ### Historical inventory

A full `npm audit --json` returned **7 affected package entries: 1 critical, 5 moderate, 1 low**. Parent-package entries include transitive advisory propagation; this does not mean seven independent app exploits.

| Installed package | Audit severity | Scope / follow-up |
| --- | --- | --- |
| DOMPurify 3.4.15 | Critical | Monaco embeds this version in its prebuilt `min/vs` browser files, which `prepare-editor.cjs` copies to the app. A lockfile-only override does not replace that embedded runtime. Upstream lists 3.4.17 as the fix for [GHSA-cg2g-xh64-v4q7](https://github.com/advisories/GHSA-cg2g-xh64-v4q7); additional DOMPurify advisories also apply to the installed version. |
| Monaco Editor 0.57.0 | Low | Transitive DOMPurify package entry. Patched browser assets must be rebuilt or obtained from a verified patched upstream build, then editor/diff/find/hover tests rerun. |
| glob 13.0.6 | Moderate | Build-tool dependency; [cancellation traversal advisory](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), fixed in 14.0.2+. |
| minimatch 10.2.6 | Moderate | Build-tool dependency; [pattern amplification advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249), fixed in 11.0.1+. |
| @electron/asar 4.3.1 | Moderate | Propagated from glob/minimatch; changing major transitive versions requires packaging compatibility checks. |
| @electron/universal 3.0.6 | Moderate | Propagated through asar. |
| @electron/packager 20.3.0 | Moderate | Propagated through asar/universal. Do not apply npm's suggested major downgrades without reviewing the actual bundled dependencies. |

The DOMPurify critical advisory depends on specific sanitizer modes/input conditions. This review found the affected embedded library, but did not demonstrate that those exploit conditions are reachable in el-d90. It is therefore a dependency remediation item, not a validated claim of an exploitable el-d90 XSS. The current latest package metadata still reported Monaco 0.57.0 and packager 20.3.0, so a blind `npm update` is insufficient.
