## What’s new in 0.5.2

### Cluster visibility and history

- A dedicated Cluster dashboard shows CPU, memory and Pod capacity across namespaces, with worker/control-plane filters.
- CPU and memory history is available for Nodes, Pods, Deployments, StatefulSets, DaemonSets, Jobs, CronJobs, ReplicaSets and ReplicationControllers. Workload charts include applicable container, request/limit, network and filesystem views.
- Shared time ranges include 5 minutes, 30 minutes, 1/2/4/6/24 hours, 7 days and custom windows. Hover for samples, drag to zoom, reset zoom, export PNG/CSV, or diagnose missing monitoring series.
- Resource maps show relationships among ingress, services, workloads, Pods and storage. Custom resources are grouped by API group, and navigation groups collapse independently.

### Everyday workflows

- Namespace checkboxes apply immediately, support multiple selections, and provide individual removal and Clear all.
- Resource tables have columns specific to each resource type, persisted column choices, sorting and CSV export. Pod and deployment tables show current memory/CPU usage; Nodes include usage bars.
- Favorite resources and save named cluster/namespace/filter views locally. Global search finds names, kinds, namespaces and labels across selected connected clusters, returning metadata only.
- The log viewer adds literal/regex search, severity and Pod/container filters, JSON formatting, timestamps and pause/resume. Buffers are bounded, and expensive regex patterns time out.
- Click outside pop-ups, resource details and dialogs to dismiss them. Unsaved resource YAML stays in memory for reopening, and dismissing Settings cancels unsaved appearance previews.

### Appearance, safety and setup

- Choose light, dark or system appearance, adjust text size, and use a one-color smart palette with live preview or advanced color customization.
- Configure custom kubeconfig paths through Settings, its YAML editor or the file picker.
- Troubleshooting highlights Pod crashes, OOM kills, image/scheduling failures, missing replicas, failed Jobs, Node conditions and Warning Events, with links to evidence.
- Per-cluster production badges and backend-enforced read-only mode help distinguish environments. Resource buttons use Kubernetes permission reviews, including exact action checks when EKS cannot list complete rules.
- Local change history records action metadata without YAML, Helm values, terminal input or resource output. Manual update checks show official GitHub release notes; setup checks inspect local kubectl, Helm and AWS CLI versions.

### Performance and fixes

- Startup restores the active view first and defers inactive cluster loads. Resource/metrics reads run concurrently and identical in-flight list reads are shared.
- Large resource tables render a scrolling window; sorting and CSV exports still cover the complete loaded result. Search is debounced, and obsolete snapshot/chart/search requests are cancelled.
- Oversized Kubernetes list responses use paginated reads. Secret list responses retain only permitted metadata and key names. Historical CSV exports guard against spreadsheet formula injection.

## Validation and requirements

Validated with **154 backend checks and 13 desktop acceptance suites**, including packaged-app checks for namespace selection, click-away dismissal, YAML recovery and theme-preview cancellation. The 10,000-row table checks cover scrolling, sorting, column visibility and full CSV export. Live staging verification used read-only requests; no cluster credentials or local profiles are bundled.

Historical charts require a compatible Prometheus stack and retained samples; current usage requires the Kubernetes Metrics API. Missing permissions or metrics are reported as unavailable or partial coverage. This release remains **ad-hoc signed, without Apple Developer ID signing or notarization**.
